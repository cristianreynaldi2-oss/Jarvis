## Development Workflow

Selama pengembangan, gunakan workflow berikut.

1. Jelaskan tujuan milestone yang akan dikerjakan.
2. Jelaskan konsep secara singkat.
3. Berikan langkah implementasi yang jelas dan berurutan.
4. Setelah implementasi selesai, lakukan testing.
5. Jika ditemukan bug, fokus debugging terlebih dahulu.
6. Setelah semua stabil, lakukan Git Commit menggunakan Conventional Commit.
7. Baru lanjut ke milestone berikutnya.

Jangan melompati langkah.

## Collaboration Rules

- Jangan langsung memberikan seluruh solusi sekaligus.
- Mulai dari penjelasan singkat, kemudian lanjut ke implementasi.
- Berikan instruksi yang lengkap dan tidak setengah-setengah.
- Jika ada perubahan pada file yang sudah ada, jelaskan file mana yang diubah serta tampilkan isi akhir yang harus menjadi hasilnya.
- Jangan mengubah struktur project tanpa alasan yang jelas.
- Jika ada refactor, jelaskan alasan refactor tersebut.
- Selalu akhiri setiap milestone dengan:
  - Yang harus saya lakukan sekarang
  - Checklist testing
  - Git Commit yang disarankan
  - Milestone berikutnya

- Fokus menyelesaikan satu milestone hingga stabil sebelum berpindah ke milestone berikutnya.

---

## Instruction Standard

Setiap implementasi harus mengikuti format berikut.

1. Tujuan
2. Penjelasan singkat
3. File yang dibuat
4. File yang diubah
5. Isi akhir setiap file yang berubah (jika perubahan cukup besar)
6. Langkah testing
7. Yang harus saya lakukan sekarang
8. Git Commit (jika milestone selesai)
9. Preview milestone berikutnya

Silakan baca PROJECT.md terlebih dahulu sebagai konteks utama proyek, kemudian gunakan CHANGELOG.md untuk melihat perubahan terakhir sebelum memulai Sprint.
